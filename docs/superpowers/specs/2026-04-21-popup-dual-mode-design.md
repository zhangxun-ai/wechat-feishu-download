# Popup 双层模式重构设计

**目标**

把现有扩展弹窗从“功能堆叠页”重构为“默认极简 + 高级工作台”的双层模式，优先服务“当前页一键导出”，同时保留批量下载、公众号后台模式、Obsidian 配置这些进阶能力。

这次重构需要解决两个现有问题：

- 默认弹窗信息过多，新手很难判断当前最该点哪个按钮
- Obsidian、批量下载、公众号后台这些能力和当前页导出混在一起，缺少明显的层级

**范围**

- 重构 `popup.html` 与 `popup.css` 的信息架构
- 为 popup 增加“当前页主操作”模型
- 新增统一输出目标模型：`仅下载 / 两者都要 / 仅 Obsidian`
- 在批量任务与专栏任务里支持新的输出目标语义
- 保留现有导出、批量下载、公众号后台和 Obsidian 授权能力

**非目标**

- 不重写 batch runner 的整体视觉样式
- 不新增任务中心完整历史列表
- 不新增 NotebookLM 专用打包模式
- 不重构现有内容抽取链路

## 用户体验

### 默认层

弹窗默认只展示 4 块内容：

1. 当前页状态
2. 当前页主操作
3. 快速设置
4. 高级工作台入口

当前页主操作根据上下文动态变化：

- 普通正文页：`导出当前文档`
- 生财专栏页：主按钮 `导出当前专栏`，次按钮 `仅导出当前文档`
- 公众号后台页：提示进入高级工作台继续配置下载范围
- 不支持页面：主按钮禁用

快速设置只保留高频选项：

- 输出目标
- 图片开关
- Obsidian 连接摘要

### 高级层

点击 `展开高级工作台` 后，显示完整工作台，包含 4 个区块：

1. 当前页高级操作
2. 批量链接下载
3. 公众号后台模式
4. Obsidian 目录配置

高级层不再承担默认入口角色，而是承载低频、高复杂度操作。

## 输出目标模型

输出目标统一为以下 3 种：

- `download`
  - 只下载本地文件
- `both`
  - 下载本地文件，同时写入 Obsidian
- `obsidian`
  - 不触发浏览器下载，只写入 Obsidian

规则：

- 单篇 Markdown 导出：3 种模式都支持
- 批量链接下载：3 种模式都支持
- SCYS 专栏导出：
  - `download`：保留 Markdown + HTML 下载
  - `both`：下载 Markdown + HTML，并写入 Obsidian 知识库包
  - `obsidian`：只写入 Obsidian 知识库包，不再下载 Markdown + HTML

## 架构方案

### UI 模型

新增一个纯函数模块，负责：

- 解析输出目标
- 构建当前页主操作模型

这层逻辑不依赖 DOM，方便测试，也避免把弹窗逻辑继续堆在 `popup.js` 中。

### Popup 状态

`popup.js` 负责：

- 读取当前标签页上下文
- 渲染默认层
- 维护高级层展开状态
- 将输出目标同步到本地存储
- 在需要 Obsidian 时提前做目录可用性检查

### Batch Runner 状态

`batch-runner.js` 负责：

- 根据任务中的 `outputTarget` 决定是否下载、是否写入 Obsidian
- 调整结果文案与元信息展示

## 成功标准

- 默认弹窗打开后，用户能在 3 秒内理解“当前最该点什么”
- 不常用能力不会默认占据主要视觉空间
- Obsidian 不再以独立大面板抢占默认页
- 现有任务类型在新输出目标模型下行为一致
