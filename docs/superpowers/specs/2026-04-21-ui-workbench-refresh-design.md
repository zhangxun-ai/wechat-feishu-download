# UI 工作台改版设计

- 日期：2026-04-21
- 项目：`my_feishu_clipper_youxia`
- 主题：Popup 与任务页视觉改版
- 状态：已确认，可进入实现

## 1. 背景与目标

当前插件功能已经基本可用，重点不再是继续加能力，而是提升：

- 页面整洁度
- 主次层级清晰度
- 首屏扫描效率
- 视觉质感与专业感
- 低频设置对高频操作的干扰控制

本轮改版必须满足两个硬约束：

- 不影响现有导出功能与流程
- 不改变现有核心能力，只优化信息架构、视觉表达和交互呈现

## 2. 设计结论

本轮采用如下方向：

- 总体方向：`B 分类工作台`
- 首屏密度：`适中`
- 分类结构固定为四类：
  - 微信公众号
  - 飞书
  - 生财有术
  - 其它

其中 `其它` 用于承接不属于前三类的普通网页与平台文章，包括但不限于：

- X
- 小红书
- 其他普通网页文章页

## 3. 设计原则

### 3.1 以效率优先，不做功能堆叠

打开 popup 后，用户应在最短时间内完成三件事：

1. 理解当前页面被识别成什么类型
2. 知道当前最适合执行的主操作
3. 用最少的思考完成导出

### 3.2 预设优先，参数后置

首屏先表达“我要拿这份内容去做什么”，而不是让用户先拼装技术参数。

### 3.3 当前场景优先

页面只优先展示当前分类最相关的能力。其他分类的能力不在首屏抢占注意力。

### 3.4 更克制的视觉表达

高级感来自于：

- 更少的卡片层
- 更稳定的对齐和留白
- 更清晰的主次关系
- 更短的说明文案

而不是来自更多装饰、更多渐变或更多色块。

## 4. Popup 信息架构

新版 popup 调整为以下结构。

### 4.1 顶部窄栏

用途：

- 展示插件标题
- 展示当前识别到的分类状态
- 提供一个极简设置入口

约束：

- 不再保留占高度较大的 hero 说明区
- 标题和说明必须压缩到一屏上方的窄区域

### 4.2 分类导航栏

固定 4 个 tab：

- 微信公众号
- 飞书
- 生财有术
- 其它

行为规则：

- 打开弹窗时自动识别当前页面分类
- 自动切换到识别后的对应 tab
- 若识别失败或页面不在已知分类中，默认落到 `其它`

### 4.3 主操作区

这是 popup 的视觉重心，必须保留：

- 当前页标题
- 页面类型
- 当前可执行动作摘要
- 一个主按钮
- 一个次按钮

示例：

- 生财课程章节页：
  - 主按钮：`导出当前专栏`
  - 次按钮：`仅导出当前章节`
- 普通网页：
  - 主按钮：`导出当前网页`
- 公众号后台模式：
  - 主按钮：`按范围批量下载`

设计要求：

- 每个场景只有一个真正的主按钮
- 次按钮只承担补充动作，不得争抢视觉中心

### 4.4 导出预设区

首屏保留一个小型预设区，用意图替代参数组合。

预设固定为：

- `快速导出`
- `发给 AI`
- `存到 Obsidian`

预设含义：

- 快速导出：以下载留档为主，适合常规保存
- 发给 AI：更偏向轻量 Markdown 与分析场景
- 存到 Obsidian：以落入 Vault 为主

要求：

- 预设是首屏可见的
- 更细的配置仍保留，但放入“更多设置”或次级区域
- 底层现有输出能力不变，只改变交互表达方式

### 4.5 分类专属工作区

分类专属区只展示当前分类真正需要的工具，不做跨分类平铺。

#### 微信公众号

保留：

- 后台登录状态
- 种子链接
- 日期范围
- 批量下载入口

#### 飞书

保留：

- 批量链接输入
- 批量下载入口

#### 生财有术

保留：

- 专栏导出说明
- 专栏导出主入口
- 当前章节导出补充入口

#### 其它

保留：

- 普通网页导出说明
- 与通用正文导出兼容的提示

### 4.6 底部轻量状态条

Obsidian 不再占用一整块大卡片，而是改成轻量底部状态区。

显示内容：

- 当前目标目录
- 授权状态
- 修改入口

目标：

- 始终可见
- 不抢夺首屏注意力

## 5. 任务页信息架构

`batch-runner` 的目标不是做“日志中心”，而是做“安静的任务页”。

### 5.1 顶部摘要区

保留：

- 任务名称
- 总数量
- 通道数
- 耗时
- 当前总体状态

### 5.2 结果优先区

完成后最优先展示：

- 打开 Markdown
- 打开 HTML
- 打开 Obsidian 目录

要求：

- 结果动作必须比日志更显眼
- 成功结果与失败状态必须一眼区分

### 5.3 摘要统计区

保留当前统计能力：

- 进度
- 成功
- 失败
- 通道
- 耗时

但表现上更收敛，不让卡片过度抢视觉注意力。

### 5.4 通道与日志默认弱化

并行通道和详细日志依然保留，但默认不抢占视觉重心：

- 通道区可折叠或弱化展示
- 日志区默认作为次级信息
- 用户需要时再展开查看

## 6. 视觉语言规范

### 6.1 背景

- 保留暖米色调
- 降低背景本身的存在感
- 让内容层级而不是背景效果承担主要视觉组织任务

### 6.2 卡片体系

- 减少“每块都是卡片”的感觉
- 页面只保留少量必要的强卡片
- 次级区域通过留白、字重、分隔来建立层级

### 6.3 按钮体系

- 每屏只有一个最强主按钮
- 次按钮统一为浅底或描边样式
- 不允许出现两个同等级主按钮并列争抢注意力

### 6.4 颜色使用规则

主橙色只用于：

- 主按钮
- 激活分类
- 选中预设
- 关键高优先级状态

成功、失败、提示的状态色必须更克制，避免大面积高饱和铺色。

### 6.5 文案规则

- 首屏只说动作，不重复解释背景
- 低频说明后置
- 同一概念不在多个区域重复描述

## 7. 不改动的功能边界

本轮明确不改以下能力逻辑：

- 页面识别逻辑
- 各分类已有导出能力
- 生财有术专栏导出流程
- 批量任务执行机制
- Obsidian 写入能力
- 导出格式支持范围

如果实现过程中出现需要改动上述能力逻辑的情况，应视为越界，必须单独评估。

## 8. 验收标准

### 8.1 Popup

- 打开后 1 屏内可完成主要判断与操作
- 自动落到正确分类；识别失败时落到 `其它`
- 用户能在不展开额外设置的前提下完成常见导出
- 预设表达清晰，不影响已有输出能力
- Obsidian 状态可见但不喧宾夺主

### 8.2 任务页

- 运行中能快速看懂总体状态
- 完成后优先看到结果动作，不需要先读日志
- 通道与日志仍可查看，但不会成为页面视觉中心

### 8.3 稳定性

- 现有导出功能全部保持可用
- 现有按钮行为和底层逻辑不回归
- 不因样式或结构调整造成事件绑定失效

## 9. 实施建议

实现应优先分为两个阶段：

1. 先完成结构重排与文案减法
2. 再完成视觉样式收敛与细节打磨

这样可以降低一次性大改带来的回归风险。
